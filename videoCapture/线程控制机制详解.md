# 五路流线程控制机制详解

## 整体控制架构

这个项目采用了**事件驱动 + 线程池**的架构来控制五路流的启动、停止和销毁。整个控制流程如下：

```
用户操作 → UI事件 → 事件队列 → 事件循环 → 线程池 → 具体线程控制
```

## 1. 事件系统架构

### 核心组件
- **FFEventQueue**: 全局事件队列，单例模式
- **FFEventLoop**: 事件循环线程，持续处理事件
- **FFThreadPool**: 线程池，执行具体的事件处理任务
- **各种Event**: 具体的事件类型

### 事件类型
```cpp
// 打开源事件
FFOpenSourceEvent - 启动某个源（摄像头、屏幕、音频等）
FFCloseSourceEvent - 关闭某个源

// 控制事件  
FFStartEvent - 开始录制/直播
FFStopEvent - 停止录制/直播
FFPauseEvent - 暂停/恢复

// 参数调整事件
FFBeautyEvent - 美颜参数调整
FFVolumeEvent - 音量调整
```

```cpp
// FFOpenSourceEvent::work() 执行流程
void FFOpenSourceEvent::work()
{
    init();    // 初始化解复用器和解码器
    start();   // 启动相关线程
}

void FFOpenSourceEvent::start()
{
    if(sourceType == AUDIO || sourceType == MICROPHONE){
        // 启动音频相关线程
        aDemuxerThread[index]->start();
        aDecoderThread[index]->start();
        aPktQueue[index]->start();
        aFrmQueue[index]->start();
        aFilterThread->openAudioSource(sourceType);
    }
    else{
        // 启动视频相关线程
        vDemuxerThread[index]->start();
        vDecoderThread[index]->start();
        vPktQueue[index]->start();
        vFrmQueue[index]->start();
        vFilterThread->openVideoSource(sourceType);
    }
}
```

### 2.2 线程停止控制

#### 关闭源事件
```cpp
void FFCloseSourceEvent::close()
{
    if(sourceType == AUDIO || sourceType == MICROPHONE){
        // 停止音频线程
        aDemuxerThread[index]->stop();
        aDemuxerThread[index]->wakeAllThread();
        aDemuxerThread[index]->wait();
        aDemuxerThread[index]->close();
        
        aDecoderThread[index]->stop();
        aDecoderThread[index]->wakeAllThread();
        aDecoderThread[index]->wait();
        aDecoderThread[index]->close();
        
        // 清空队列
        aPktQueue[index]->close();
        aFrmQueue[index]->close();
        
        // 通知过滤器线程
        aFilterThread->closeAudioSource(sourceType);
    }
    // 视频源类似处理...
}
```

### 2.3 线程状态管理

#### 基础线程类 (FFThread)
```cpp
class FFThread {
protected:
    std::atomic<bool> m_stop;  // 停止标志
    std::thread m_thread;      // 线程对象
    
public:
    void start() {
        m_stop = false;
        m_thread = std::thread(&FFThread::run, this);
    }
    
    void stop() {
        m_stop = true;
    }
    
    void wait() {
        if(m_thread.joinable()) {
            m_thread.join();
        }
    }
};
```

#### 队列控制机制
```cpp
// 队列的线程安全控制
class FFVPacketQueue {
private:
    std::mutex mutex;
    std::condition_variable cond;
    std::atomic<bool> m_stop;
    
public:
    void wakeAllThread() {
        m_stop = true;
        cond.notify_all();  // 唤醒所有等待的线程
    }
    
    void start() {
        m_stop = false;     // 重置停止标志
    }
};
```

## 4. 核心过滤线程控制

### FFVFilterThread 的状态管理
```cpp
class FFVFilterThread {
private:
    std::atomic<bool> cameraFlag;    // 摄像头流标志
    std::atomic<bool> screenFlag;    // 屏幕流标志  
    std::atomic<bool> videoFlag;     // 视频流标志
    std::atomic<bool> encoderFlag;  // 编码标志
    std::atomic<bool> pauseFlag;    // 暂停标志
    
public:
    void openVideoSource(int sourceType) {
        switch(sourceType) {
            case SCREEN: screenFlag.store(true); break;
            case CAMERA: cameraFlag.store(true); break;
            case VIDEO: videoFlag.store(true); break;
        }
    }
    
    void closeVideoSource(int sourceType) {
        switch(sourceType) {
            case SCREEN: screenFlag.store(false); break;
            case CAMERA: cameraFlag.store(false); break;
            case VIDEO: videoFlag.store(false); break;
        }
    }
};
```

## 5. 线程销毁机制

### 5.1 优雅关闭流程
```cpp
void FFCaptureUtil::stopCapture()
{
    // 1. 停止过滤线程
    if(m_vFilterThread) {
        m_vFilterThread->stop();
        m_vFilterThread->wakeAllThread();
        m_vFilterThread->wait();
    }
    
    // 2. 停止事件循环
    if(m_eventLoop) {
        m_eventLoop->stop();
        m_eventLoop->wakeAllThread();
        m_eventLoop->wait();
    }
    
    // 3. 隐藏窗口
    if(m_capWindow) {
        m_capWindow->hide();
    }
}
```

## 6. 控制流程图

```
用户操作
    ↓
UI事件处理
    ↓
创建对应Event对象
    ↓
加入FFEventQueue
    ↓
FFEventLoop取出事件
    ↓
提交给FFThreadPool
    ↓
执行Event::work()
    ↓
根据事件类型控制对应线程
    ↓
更新线程状态标志
    ↓
线程根据标志决定是否工作
```

## 7. 关键设计特点

### 7.1 异步事件处理
- 所有线程控制都通过事件异步处理
- 避免UI阻塞，提升用户体验
- 支持并发操作多个源

### 7.2 状态标志控制
- 使用 `std::atomic<bool>` 确保线程安全
- 各线程根据状态标志决定是否工作
- 支持动态开启/关闭各路流

### 7.3 优雅的资源管理
- 队列支持阻塞等待，避免忙等待
- 线程支持优雅关闭和资源清理
- 防止资源泄漏和死锁

### 7.4 灵活的架构设计
- 事件驱动架构易于扩展
- 线程池提高并发性能
- 模块化设计便于维护

这种设计使得五路流的控制非常灵活和高效，用户可以通过UI动态控制各个源的开启和关闭，系统会自动管理相关的线程和资源。
